# G4-6（現在の UniQ-DETR）の手法まとめ

2026-11-07 時点の UniQ-DETR の学習設定です（`configs/g4_6.yml`、推論は `configs/uniq_detr.yml`）。
経緯と全実験は `analysis/G4_PLAN.md` にあり、ここでは手法そのものと、その根拠になった結果だけをまとめます。

## 1. 概要

- **目的：** M-OWODB Task 1 で、NMS を使わず（topk だけで）既知物体と未知物体を同時に検出します。
- **ベース：** RT-DETRv2（PResNet-50、640×640、デコーダ 6 層）です。バックボーンは ImageNet 事前学習の重みだけを使います。
- **追加するもの：**
  1. デコーダの各層に、クラスによらない軽いヘッドを 4 つ付けます：o・u・q・r。
  2. 21 列目に unknown クラスを置きます。
  3. 学習初期の自分自身を教師にした疑似ラベルを使います。オフラインで 1 回だけ作り、外部モデルは使いません。
- **G4-6 の新しい点：** 1 対 1 ヘッド r を、既知 GT だけでなく疑似ラベルの箱でも学習します。
- **結果：** Known AP50 63.78 / U-Recall 29.63 / WI 0.052 / A-OSE 3,656 / 108 FPS（fp32、RTX 4090、バッチ 1）。

## 2. 構成

```
画像 → PResNet-50 → HybridEncoder → クエリ選択（エンコーダのスコア上位 Q 個）→ デコーダ 6 層
                                                                    └ 各層の出力クエリ（256 次元）に
                                                                      ・クラスヘッド（21 列：既知 20 ＋ unknown）
                                                                      ・箱ヘッド
                                                                      ・o / u / q / r ヘッド（各 1 出力）
                                                                      ・nc ヘッド（OW-DETR の NC 枝。学習だけで、推論では使わない）
```

- **クエリ数：** 学習は 600、推論は 900 です。G4-4 からの設定です。
- **デノイジング：** RT-DETRv2 のまま 100 です。疑似ラベルの箱はデノイジングに入れません（`OWRTDETRTransformerv2.pseudo_label: 20`）。

## 3. ヘッドと損失

既知 GT は、各層で Hungarian マッチングにより対応付けます（RT-DETRv2 のまま、VFL・L1・GIoU）。疑似ラベルはマッチングの前に取り分けておくので、既知 GT のマッチングには入りません。

| 項目 | 何を表すか | 学習の目標 | 重み |
|---|---|---|---:|
| クラス（既知 20 列） | p(c) | 既知 GT に対応付いたクエリ（VFL） | 1 |
| クラス（unknown 列） | 未知の物体 | 疑似ラベルの箱に割り当てたクエリ = 正例（VFL、目標は箱との IoU） | 1（VFL に含まれる） |
| 箱 | 位置 | 既知 GT だけ（L1 / GIoU） | 5 / 2 |
| 物体らしさ o | 全クエリの分布からの距離 d²（BatchNorm 後の二乗ノルム、PROB と同じ）。o = exp(−1.3·d²/256) | 既知 GT に対応付いたクエリの d² を小さくする。統計は全クエリから取る | 0.3 |
| 既知以外 u | 既知クラスに対応付かないクエリか | 未マッチのクエリ = 1、既知に対応付いたクエリ = 0（focal、空の重み 0.1） | 1 |
| 位置の当てはまり具合 q | クラス非依存の IoU 予測（OLN） | 既知 GT と IoU ≥ 0.3 のクエリだけ、その IoU を目標にする（BCE）。背景には損失をかけない | 1 |
| **1 対 1 ヘッド r** | そのクエリが物体を代表する 1 個か | **既知 GT と疑似ラベルの箱**に対応付いたクエリ = 1、同じ箱と IoU ≥ 0.5 の他のクエリ = 0。どの箱からも遠いクエリには損失なし（BCE） | 1 |
| nc | OW-DETR の NC 枝 | 既知 GT と疑似ラベルの正例 = 1（focal） | 0.05 |

- **r がこの手法の中心です。**
  - 既知クラスが NMS なしで重複しないのは、1 対 1 マッチングのおかげです。
  - r はこの性質を「クラスによらず、物体ごとに代表を 1 個」という形で学ぶので、未知物体の重複も抑えられます。
  - 背景には損失をかけないので、未知物体を背景として抑え込みません。案 F2 は、背景を負例にしたことで未知物体まで抑え込んでしまい、失敗しました。
- **G4-6 の変更：** 以前の r は既知 GT だけで学習していました。G4-6 では、疑似ラベルの箱（とその重複）も r の目標に入れています（`OWCriterion.pseudo_primary: True`）。

## 4. 疑似ラベル（G4-1 から変わらず）

### 4.1 教師
- 構成は `configs/e2_obj.yml` です。RT-DETRv2 に o と u だけを付けたもので、300 クエリです。
- 既知 20 クラスの GT だけで **2 エポック**学習した重み（`outputs/e2_pilot_bn/last.pth`）を使います。
- 学習初期の重みを使うのは、未知物体がまだ背景として抑え込まれていないからです。V1 プローブ（COCO 学習画像 3,000 枚・unknown GT 9,892 個）で、候補が未知物体に当たる割合を測りました。

  | 教師 | 当たる割合 |
  |---|---:|
  | エポック 2 | 9.6% |
  | エポック 10 | 9.0% |
  | エポック 50 | 4.7% |
  | OW-DETR の注意（C4 活性） | 3.2% |

### 4.2 作り方（`tools/make_pseudo_unk.py`、学習画像 16,551 枚）
1. 教師の予測箱を、元の画像と左右反転した画像の両方で得ます。データ拡張はしません。
2. 既知 GT のどれとも IoU 0.5 未満の箱を候補にします。
3. 各候補に反転一致度を付けます。反転画像の予測を元の向きに戻し、その中で最も重なる箱との IoU です。
4. 反転一致度で並べ、クラスを区別しない NMS（IoU 0.5）をかけ、上位 5 個を残します。この NMS は疑似ラベルを作るときだけで、推論には入りません。
5. `data/pseudo_unk/e2ep2_cons_k5.json`（82,000 個、1 画像あたり 4.95 個）に、`category_id = 20` として保存します。

V1 プローブでの質は、精度 9.9%・再現率 13.9% です。

### 4.3 学習での使い方
- エポック 9（`attn_pseudo_start`）から使います。
- 各デコーダ層で、疑似ラベル 1 個につき、IoU ≥ 0.5 で最も重なる未マッチのクエリ 1 個を割り当てます。貪欲法で割り当て、1 クエリは 1 個の箱にしか使いません。
- 割り当てたクエリは、次の 3 か所で正例になります。
  - unknown 列の VFL
  - nc
  - r（G4-6 から）
- 疑似ラベルの箱は、箱の損失と既知 GT の正規化の数には入れません。
- **効く理由：** 精度が 1 割でも効くのは、ラベルが正しいからではありません。GT のないクエリの一部を背景として抑え込まないことが効いています（`docs/BASELINES_RESULTS.md` §7）。教師の箱は OW-DETR の注意より約 3 倍多く未知物体の上に乗るので、その効果が未知物体に集まります。

## 5. 学習設定

| 項目 | 値 |
|---|---|
| エポック | 50（GPU 1 枚で約 8 時間） |
| バッチ | 16 |
| 最適化 | AdamW。学習率 1e-4、バックボーンは 1e-5、weight decay 1e-4。warmup 2,000 iter。勾配クリップ 0.1 |
| EMA | 0.9999（warmup 2,000） |
| データ拡張 | RT-DETRv2 のまま：PhotometricDistort、ZoomOut、IoUCrop、反転、マルチスケール 480〜800。最後の 2 エポック（48〜）は強い拡張を止める |
| 疑似ラベルの開始 | エポック 9（unknown 列・nc・r のすべて。それまでは G4-4 と同じ学習） |
| 精度 | fp32（AMP なし） |

## 6. 推論

- **クエリ：** 900（学習は 600）です。デコーダの重みはクエリ数によらないので、選ぶ数を増やすだけです。
- **スコア行列 [900 × 21]：**
  - 既知の 20 列：p(c)
  - unknown の 1 列：**w · o · σ(u) · q · σ(r) · (w_box · h_box)^0.25**
    - w = 12
    - 箱の面積は 0〜1 に正規化した値
    - q は σ 後の IoU 予測
- 行列全体から上位 100 件を出力します。NMS も重複除去もしません。
- **追加の計算：** 要素ごとの積だけです。速度は 108 FPS（fp32）、86 FPS（AMP）です。
- **設定の選び方：**
  - テスト画像を名前の偶奇で 2 分割し、片方（tune）で選んで、もう片方（report）で報告します。
  - UniQ-DETR は、tune の Known AP50 ≥ 63.5 の中で U-Recall が最大の設定にしました。
  - 通常の基準（≥ 61.51）にすると w 24 になり、61.50 / 30.48 です。

## 7. 結果

### 7.1 比較（report 側、top-100）

| 手法 | 後処理 | Known AP50 | U-Recall | WI | A-OSE | FPS |
|---|---|---:|---:|---:|---:|---:|
| **UniQ-DETR（G4-6）** | **topk** | 63.78 | **29.63** | 0.052 | 3,656 | 108 |
| OW-DETR-RT | NMS 0.5 | 62.30 | 27.83 | 0.055 | 7,295 | 95〜98 |
| CAT-RT | NMS 0.7 | 62.50 | 26.28 | 0.057 | 11,327 | 70 |
| PROB-RT | NMS 0.7 | 62.26 | 24.66 | 0.070 | 4,812 | 93〜95 |
| RandBox-RT | NMS 0.5 | 61.85 | 24.03 | 0.036 | 5,336 | 13.5 |
| OrthogonalDet-RT | NMS 0.5 | **65.22** | 19.45 | **0.029** | **1,993** | 12.0 |

比較手法は、同じ RT-DETRv2・同じ学習レシピに移植したものです（`analysis/G3_SUMMARY.md`）。

### 7.2 段階ごとの改善（report 側）

| 段階 | 変更 | Known AP50 | U-Recall |
|---|---|---:|---:|
| 案 G3 | r ＋ OW-DETR の疑似ラベル（300 クエリ） | 62.61 | 23.92 |
| G4-1 | 疑似ラベルを学習初期の教師の箱に置き換え | 62.17 | 25.99 |
| G4-4 | 600 クエリで学習 | 62.87 | 27.24 |
| G4-4 ＋ 推論 | 900 クエリで推論、面積の項 | 63.53 | 28.69 |
| **G4-6** | **r も疑似ラベルの箱で学習**、r の指数 0.5 → 1 | **63.78** | **29.63** |

### 7.3 G4-6 の効果（G4-4 との比較、900 クエリ）

| tune の Known の下限 | G4-6 | G4-4 |
|---|---|---|
| ≥ 61.51 | 61.50 / **30.48** | 61.94 / 29.16 |
| ≥ 63.5 | **63.78 / 29.63** | 63.53 / 28.69 |

- **最適な r の指数が 0.5 から 1 に変わった：** r が疑似ラベルの箱でも学習されて信頼できるようになったためです。G4-4 の設定（r^0.5）のままだと 62.96 / 27.95 で、かえって下がります。
  - r の指数と U-Recall の最大値：0.75 → 30.13、1 → 30.48、1.5 → 29.66、2 → 28.62。
- **取りこぼしの減少：** 取りこぼした unknown に最も重なるクエリの σ(r) は、中央値 0.08 → 0.15 に上がりました。大きい unknown の拾えた割合は 68% → 73% です。
- **推論のクエリ数：** 900 の方が 600 より U-Recall が 0.5〜0.8 高いです。
- **学習中の評価**（w 1、面積の項なし）：最終エポックで 64.33 / 18.07（G4-4 は 64.04 / 15.95）。

| 試したこと | 結果 | 記録 |
|---|---|---|
| 1 対多の補助学習（G4-3、H-DETR） | クエリを増やすと Known AP50 が 30 前後に崩れる。600 クエリと組み合わせられない | G4_PLAN §6.4 |
| 900 クエリで学習（G4-5） | 61.81 / 26.46。600 クエリで学習して 900 で推論する方が良い | G4_PLAN §6.6 |

| 疑似ラベルの更新（置き換え・EMA・追加・除外） | 今の上位 5 個より良くならない。教師が再現する箱で絞る方法だけが約 +1pt | 同上 |
| 疑似ラベルを上位 10 / 15 個に（G4-7a / b） | 学習中の w 1 では U-Recall が上がるが、掃引後は差が ±0.5 以内。Known ≥ 63.5 では上位 5 個が最良 | 同上 |
| 疑似ラベルを箱の大きさで絞る | 同じ箱数の上位 k と同じ精度・再現率 | 同上 |
| アテンション（エンコーダの self-attention、デコーダの cross-attention）で順位付け | どれも反転一致度より弱い（AUROC 0.42〜0.64 対 0.745）。組み合わせても約 +1pt | 同上 |
| 推論解像度を 800 / 960 に | 網羅率が下がる（小さい unknown 43.7 → 36.8 / 30.1%） | 同上 |

## 9. 残っている課題

- **Known AP50：** OrthogonalDet-RT の 65.22 に 1.4 届きません。
- **小さい unknown：** 拾えた割合は約 20% です。原因はデコーダより前にあります（`tools/diag_small_cov.py`、900 クエリ）。

  | unknown の GT | エンコーダの全提案が覆う | 選ばれた提案が覆う | デコーダの最終の箱が覆う |
  |---|---:|---:|---:|
  | 小 | 55.8% | 43.1% | 43.7% |
  | 中 | 93.8% | 65.0% | 67.3% |
  | 大 | 99.6% | 87.3% | 89.0% |

  - エンコーダの箱の頭は既知 GT だけで学習しているので、小さい unknown の 44% はどの提案にも覆われません（既知の小さい物体は 20%）。
  - クエリの選択はクラスのロジットの最大で、unknown 列が学習されていません。そのため、提案はあっても選ばれない unknown が多くあります（中 −29pt）。
  - → G4-8（エンコーダも疑似ラベルの箱で学習）で検証中です。
- **A-OSE：** r の指数を 1 にした分、G4-4（2,555）より増えています（3,656）。
- **順位付け：** 覆えている unknown のうち、拾えるのは約 2/3 です。外れの σ(r) も上がっていて、r だけでは区別しきれません。

## 10. 再現

```bash
# 疑似ラベルの教師（E2、2 エポック）と疑似ラベル（上位 5 個）
uv run python tools/train.py -c configs/e2_obj.yml -u epoches=2 --output-dir outputs/e2_pilot_bn
uv run python tools/make_pseudo_unk.py -c configs/e2_obj.yml -r outputs/e2_pilot_bn/last.pth \
    --ann data/mowodb/t1_train.json --out-prefix data/pseudo_unk/e2ep2_cons --ks 5
# 学習（600 クエリ）-> outputs/g4_6/best.pth。学習後の掃引と分析まで含めると scripts/run_g4_6.sh
uv run python tools/train.py -c configs/g4_6.yml
# 評価（900 クエリ、tune / report の 2 分割）と速度
uv run python tools/sweep_pp.py -c configs/uniq_detr.yml -r outputs/g4_6/best.pth --grid unk_weight=12,24
uv run python tools/bench_fps.py -c configs/uniq_detr.yml -r outputs/g4_6/best.pth
```
