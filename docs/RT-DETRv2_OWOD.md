## 0. 本計画の構成と v1 → v2 の変更点

本計画は 2 部構成である。

- **Part I: 未知検出エンジン** — 未知物体を「背景」ではなく「unknown」として検出できる RT-DETRv2（= **M₀**）を確立する
- **Part II: 反復的語彙拡張ループ** — M₀ が出した未知 box を DAM + LLM で命名し、既知クラスに昇格させて再学習する

Part I は Part II の前提である。未知 box を出す能力がなければループは起動しない。

| | v1 | v2（本計画で採用） |
|---|---|---|
| 未知の監督源 | SAM2 のクラス非依存マスク | **検出器自身が出した未知 box** |
| 未知の扱い | 単一の "unknown" クラス | **DAM + LLM で命名し、既知クラスに昇格させる** |
| 学習 | 1回 | **命名 → 再学習 → 新たな未知 の反復** |
| SAM2 の役割 | 発見（主役） | box 整形のみ（脇役） |

**研究の問いの変化**

- v1 の問い: 「未知物体を背景から救出できるか」（＝検出の問題）
- 本計画の問い: 「**検出器は自分で語彙を獲得し続けられるか**」（＝自己教師あり語彙獲得の問題）

後者は明確に野心的で、成功すれば貢献も大きい。一方で、**自己ラベリングのループは原理的に発散する危険を内包する**。ラウンド t の偽陽性が、ラウンド t+1 の正解ラベルになるためである。本計画の設計上の重心は、この発散をどう検出し、どう止めるかに置く（§6, §10）。

v1 の SAM2 疑似ラベル（C5）と、それに依存する実験（旧 E5–E7）は主手法から外し、**M₀ の U-Recall が不足した場合のフォールバック**としてのみ残す（§4 C5）。

## 1. 目的と仮説

### 1.1 目的

ラベル付き既知クラスのみから出発し、**人手のアノテーションを一切追加せずに、検出可能なクラス語彙を自律的に拡張していく**検出器学習ループを構築する。各ラウンドで、未知として検出された領域を視覚言語モデルで記述し、言語空間でクラスとして定義し、次ラウンドの既知クラスとして学習し直す。

その前段として、リアルタイム性（T4 換算 100 FPS 以上）を維持したまま、既知クラス精度の劣化を最小限に抑えて未知物体を検出できる RT-DETRv2（M₀）を確立する。

### 1.2 仮説

**Part I: 未知検出エンジン**

| ID | 仮説 | 検証 |
|---|---|---|
| **H1** | DETR 系の未知検出失敗の主因は、未マッチクエリへの背景負例損失である。これを除去し objectness を正例のみで学習すれば、未知の検出能力が創発する | E2, E3 |
| **H2** | RT-DETR 固有のボトルネックとして、エンコーダの query selection が既知K クラス分類スコアに依存するため未知物体がデコーダに到達しない。クラス非依存 objectness への置換が必要十分に効く | E4（**Part I の最大の新規性**） |
| **H3** | 前景クエリ埋め込みの分布からのマハラノビス距離は、未知性の指標として分類ロジット由来のスコア（energy, MSP）より優れる | E1, E-score |

**Part II: 語彙拡張ループ**

| ID | 仮説 | 検証 |
|---|---|---|
| **H4** | DAM の領域キャプションは、検出器のクエリ埋め込みよりも意味的に分離可能な空間を与える。すなわち言語を経由したクラスタリングが視覚特徴の直接クラスタリングを上回る | **E-visual との比較** |
| **H5** | LLM による明示的な命名と既存クラスとの衝突判定は、匿名クラスタ ID を振るだけの場合より、学習後の検出精度と語彙の安定性を改善する | **E-anon との比較** |
| **H6** | ループは 3 ラウンド以内に語彙を単調に拡張し、既知クラス精度を崩壊させない | E-main の各ラウンド |
| **H7**（**負の仮説・最重要**） | 昇格ゲートと再検証を外すと、ループは 2〜3 ラウンドで taxonomy 崩壊または既知精度崩壊を起こす | **E-nogate**（意図的に壊す実験） |

**差別化点は 2 つ。**

- **H2**: 既存の OWOD 研究（ORE, OW-DETR, PROB）は Faster R-CNN / Deformable DETR ベースであり、RT-DETR 系のハイブリッドエンコーダ + IoU-aware query selection という構造に固有の問題は扱われていない。
- **H7**: 自己ラベリング系の研究は「うまく行った条件」しか報告しないことが多く、どこで壊れるかを示せること自体が貢献になる。また、壊れ方を先に知っておかないと、E-main が失敗したときに原因を特定できない。

### 1.3 スコープ外

- M-OWODB Task 2 以降の逐次学習（インクリメンタル）— 時間が許せば E-inc として実施、必須ではない
- オープンボキャブラリ検出（テキストクエリによる未知クラス指定）

# Part I: 未知検出エンジン（M₀ の確立）

## 4. 手法：構成要素の定義

各コンポーネントを独立にオン/オフできるよう実装し、アブレーションを可能にする。C1〜C4 を実装した検出器を **M₀** と呼び、ループの初期モデルとする。

### C1. 分離 objectness ヘッド

デコーダのクエリ埋め込み q ∈ R^256 に対し、分類ヘッドと独立した class-agnostic な objectness ヘッドを追加する。

推論時スコア:

```
既知クラス c :  s_c   = p(c|q)
未知         :  s_unk = o(q) · σ(u(q))          # u(q): 学習される「既知以外」の logit（PROB と同じ）
```

`u(q)` は分類ヘッドとは別の 1 次元 logit で、**未マッチのクエリを正例（target 1）、マッチしたクエリを負例**として focal loss（重み 0.1, PROB の empty_weight）で学習する。PROB の「unknown」クラス（index 80）と同じ扱い。

> **改訂（2026-10-16）**: 当初の未知スコア `o(q) · (1 − max_c p(c|q))` は、学習されない `1 − max p` が背景で常に ≈ 1 になるため、背景の未知スコアが既知の検出を上位 100 件から押し出した（E2 試行で Known AP50 = 0）。経緯は `docs/E2_SATURATION.md`。当初の式は E-score で比較対象として評価する。
>
> **改訂（2026-10-17）**: 既知スコアも当初は `o(q) · p(c|q)` だったが、o（≈ 0.5）を掛けると既知のスコアだけが下がり、上位 100 件の枠を未知に譲る。E2 の同じ重みで、`p(c|q)` のみにすると Known AP50 が 43.7 → 53.9、U-Recall は 21.2 → 21.1（`docs/E2_SATURATION.md` §6）。このため既知は `p(c|q)` のみとした。

### C2. 確率的 objectness 損失（負例項なし）

PROB の実装と同じく、**全デコーダクエリ（マッチ・未マッチの両方）の埋め込み分布**を対角ガウス N(μ, diag σ²) で表し、その中でマッチしたクエリを中心に寄せる。

**統計の更新**（各イテレーション、EMA。PROB の BatchNorm の running 統計に相当）:
```
μ  ← (1−m)·μ  + m·mean(q_all)
σ² ← (1−m)·σ² + m·var(q_all) + ε          # m = 0.1, ε = 1e-5
```

**objectness と損失**:
```
d²(q) = Σ_k (q_k − μ_k)² / σ²_k
o(q)  = exp( −τ · d²(q) / D )              # τ = 1.3, D = 256（PROB と同じ）
L_obj = Σ_{i ∈ matched} max(d²(q_i)/D, −log 0.9) / N_box
```

**設計の核心**: 未マッチクエリは統計（基準分布）には入るが、**損失項を持たない**。したがって「物体らしいが既知クラスではない」クエリの objectness は抑圧されず保持される。これが H1 の実装。背景が基準分布を決めるため、背景の d²/D は ≈ 1（o ≈ exp(−τ) ≈ 0.27）に留まり、マッチしたクエリだけがそれより内側に寄せられる。

実装上の注意:
- μ, σ² は勾配を流さない（detach）

> **改訂（2026-10-16）**: 当初は「前景（マッチ）クエリのみの full Σ ガウス、λ = 1e-3、N イテレーションごとに更新」としていた。この設定では正例のみの損失が埋め込みを低ランクに潰し（256 次元中 199 次元が λ に張り付き、実効ランク ≈ 6）、全クエリで o(q) が飽和した（E2 v1: 平均 o = 0.84, Known AP50 = 5）。PROB の実装（全クエリの BatchNorm で正規化）とも異なっていたため、PROB の実装に合わせた。経緯は `docs/E2_SATURATION.md`。

### C3. 背景損失マスキング

```python
bg_mask = ones(num_queries, dtype=bool)
bg_mask[matched_idx] = False
unk_idx = objectness[bg_mask].topk(k_bg).indices    # 疑似未知として ignore
bg_mask[unk_idx] = False
loss_cls = focal_loss(logits[bg_mask], zeros)        # 残りのみ背景として学習
```

### C4. objectness ベース query selection ★RT-DETR 固有

RT-DETR のエンコーダは、出力トークンを既知K クラスの分類スコア上位で 300 個選びデコーダへ渡す。これを**クラス非依存 objectness スコア**での選択に置き換える。

```
変更前: top-300 by max_c sigmoid(cls_logit_c)
変更後: top-300 by sigmoid(objectness_logit)
```

エンコーダ側にも軽量な objectness ヘッド（1層 MLP）を追加し、C2 と同じ損失で学習する。IoU-aware query selection の枠組み自体は維持し、スコア定義のみ差し替える。

**これが H2 の実装であり、Part I で最も検証価値が高い改造。**

### C5. SAM2 疑似未知ラベルによる明示的監督（フォールバック・既定では無効）

E4 が §7.2 の Minimum を満たさない場合にのみ投入する。

**疑似ラベル生成（オフライン前処理）**

```
入力: Task1 学習画像 (~16.5k枚)
 1. SAM2 automatic mask generation → bbox 化
 2. フィルタ: 面積比 0.1%〜50%, アスペクト比 1:6〜6:1
 3. クラス非依存 NMS (IoU 0.7)
 4. 既知クラス GT と IoU > 0.5 の候補を除去
 5. SAM2 predicted_iou + stability_score で降順ソート、画像あたり上位 k 件を採用
出力: pseudo_unknown_task1.json (COCO形式, category_id = 81 "unknown")
```

- k はデフォルト 5。生成コストは A100 で約 4〜6 時間（1回のみ）
- **品質検査**: ランダム200枚を目視し、(a) 実物体を捉えている割合、(b) 部品レベルの過分割率を記録。前者が 60% を下回るならフィルタ条件を見直す

**matcher への組み込み**: 疑似ラベルを Hungarian matcher に**別グループ**として参加させる。

- 既知 GT: 通常の one-to-one マッチング（cls + L1 + GIoU コスト）
- 疑似未知 GT: objectness + L1 + GIoU のみでマッチング（分類コストを使わない）
- マッチした疑似未知クエリには objectness の正例損失と box 回帰損失を与える。分類損失は与えない

### C6. 対照的デノイジング（CDN）の扱い

RT-DETR の CDN における負例クエリは「わずかにズレた箱＝物体でない」を教える。これは既知クラスには有効だが未知には有害なため、**未知扱いの疑似 GT には CDN を適用しない**。

### 5.3 比較対象（文献値）

| 手法 | U-Recall (%) | Known mAP (%) | バックボーン |
|---|---:|---:|---|

# Part II: 反復的語彙拡張ループ

## 6. 提案手法

### 6.1 全体フロー

```
                    ┌─────────────────────────────────────────┐
                    │                                         │
   [Round t]        ▼                                         │
                                                              │
  M_t ──(A)──▶ 未知 box 群 B_t                                 │
   検出器       (objectness 高 / 既知クラス確率 低)             │
                    │                                         │
                   (A')  SAM2 で box 整形                      │
                    │                                         │
                    ▼                                         │
              ──(B)──▶ 領域キャプション C_t                     │
                       DAM-3B (box プロンプト)                 │
                    │                                         │
                    ▼                                         │
              ──(C)──▶ クラスタリング + LLM 命名                │
                       text embedding → HDBSCAN → Qwen         │
                    │                                         │
                    ▼                                         │
              ──(D)──▶ 昇格ゲート ★ドリフト防波堤              │
                       instance数 / 凝集度 / 衝突判定 / 語彙審査 │
                    │                                         │
                    ▼                                         │
                  語彙 V_{t+1} = V_t ∪ 新規クラス N_t          │
                    │                                         │
              ──(E)──▶ M₀ から再学習 ────────────────────────────┘
                       （M_t からではない。§6.7）
                    │
                    ▼
                  M_{t+1}
```

### 6.2 Stage A: 未知 box の抽出

M_t を学習画像全体に推論し、以下を満たす検出を未知候補とする。

```
o(q) ≥ θ_obj              かつ    max_c p(c|q) ≤ θ_cls
                          かつ    既知GT との IoU < 0.5
                          かつ    面積比 ∈ [0.3%, 50%]
```

- 画像あたり上位 **3 box** に制限（DAM のコストが支配的なため。§11）
- θ_obj, θ_cls は検証セットで U-Recall と精度のバランスから決定

**面積比の下限を厳しめに設定しているのは、DAM が小領域で幻覚を起こしやすいため。** 小さすぎる box を入れると「a small dark object」のような無内容なキャプションが大量に湧き、クラスタリングを汚す。

### 6.3 Stage A': SAM2 による box 整形

未知 box を SAM2 に box プロンプトとして与え、返ってきたマスクの外接矩形で box を置換する。

- マスクの `stability_score < 0.85` なら**整形せず元の box を使う**（SAM2 の暴走を許さない）
- 整形前後の IoU < 0.5 の場合も元を使う（別物を掴んだ可能性が高い）
- 整形後 box の面積が元の 30% 未満 → **部品を掴んだ可能性**として記録し、Stage D の衝突判定に回す

検出器の未知 box は境界が緩みがちで、緩い box のキャプションは「a person holding something near a table」のように複数物体を含んでしまう。これがクラス定義を曖昧にする主因なので、整形は費用対効果が高い工程である。

### 6.4 Stage B: DAM による領域キャプション

[DAM-3B](https://huggingface.co/nvidia/DAM-3B) に画像と box を与え、領域の詳細記述を得る。

- プロンプトは**短く物体同定に寄せる**。長い描写文は状況説明（背景、動作、色）に流れてクラスタリングを阻害する
  - 例: `"Describe the object in the marked region in a few words, focusing on what kind of object it is."`
- 生成長を 32 token に制限
- 同一 box に対し temperature 0 で 1 回のみ生成（再現性のため）
- **出力は必ず保存する**（再クラスタリングを再生成なしでやり直せるようにする。コスト管理上ほぼ必須）

### 6.5 Stage C: キャプション → クラス定義

```
1. 埋め込み: キャプションを文埋め込みモデル (gte-large 等) でベクトル化
2. クラスタリング: HDBSCAN (min_cluster_size = 30)
      → ノイズ点はクラスタ化せず「未昇格の未知」として残す ★重要
3. 各クラスタから代表キャプション 20 件をサンプリング
4. LLM (Qwen2.5-7B) に投入:
      - クラスタに簡潔な名詞クラス名を付与
      - 既存語彙 V_t の全クラス名を提示し、同一/上位/部分 のいずれかに該当するか判定
      - 該当する場合は新規クラスとせずマージ or 棄却
```

**HDBSCAN を選ぶ理由**: k-means と違いクラスタ数を事前に決めなくてよく、かつ**どのクラスタにも属さない点をノイズとして残せる**。全キャプションを無理に何かのクラスに押し込むと、それ自体がドリフトの発生源になる。ノイズ点は次ラウンドに持ち越す。

### 6.6 Stage D: 昇格ゲート（ドリフト防波堤）

クラスタが新規クラスとして語彙に入るには、**全条件を満たす必要がある**。

| # | 条件 | 既定値 | 目的 |
|---|---|---|---|
| G1 | インスタンス数 | ≥ 50 | 学習可能な最小量。長尾の尚早な昇格を防ぐ |
| G2 | キャプション凝集度（重心への平均 cos 類似） | ≥ 0.75 | 意味的に一つの概念か |
| G3 | 平均 objectness | ≥ 0.6 | box 自体の信頼性 |
| G4 | SAM2 整形の成功率 | ≥ 0.7 | 物体として輪郭が取れるか |
| G5 | 既存語彙との衝突なし | LLM 判定 | 同義語・部分・上位概念の重複を防ぐ |
| G6 | 具体名詞であること | LLM 判定 | 「blurry region」「part of something」「background」を弾く |
| G7 | 空間的多様性 | 出現画像数 ≥ 25 | 特定画像に偏った偽クラスタを弾く |

G1〜G7 を通らなかったクラスタは**破棄せず、未昇格プールに保持**して次ラウンドで再評価する。ラウンドを跨いでインスタンスが蓄積すれば昇格しうるため、長尾クラスに対する救済経路になる。

### 6.7 Stage E: 再学習

**M_t からのファインチューニングではなく、M₀（初期重み）から語彙 V_{t+1} 全体で学習し直す。**

理由: 逐次ファインチューニングは表現ドリフトを複利で蓄積させ、どのラウンドの誤りが効いているか分離できなくなる。毎回 M₀ から出直せば、ラウンド間の差分は「語彙の差」のみに帰着し、実験としての解釈可能性が保たれる。計算コストは同等（fine-tune を短くしても、収束まで見るなら大差ない）。

- 学習ラベル = 原 GT（既知20クラス、**不変**） + 昇格クラスの疑似ラベル
- **疑似ラベルには信頼度重みを掛ける**: `w = clamp(cluster_coherence × mean_objectness, 0.3, 1.0)`
- 疑似ラベルの損失重みは原 GT の 0.5 倍を上限とする
- C1〜C4（および C6）は再学習時も有効のまま（次ラウンドの未知検出能力を維持するため）

### 6.8 ループ制御と停止条件

以下のいずれかで停止:

1. 昇格クラスが 0 個のラウンドが発生
2. 残存未知に対する U-Recall の改善が 1pt 未満
3. **原 20 クラスの mAP が M₀ 比で 3pt 以上低下（tripwire。この場合は失敗として記録し、直前ラウンドにロールバック）**
4. 規定ラウンド数（3）に到達

### 6.9 ドリフト対策

自己ラベリングループの本質的な危険に対する多層防御。**ここが計画書で最も重要な節である。**

**構造的な防御**

| # | 対策 | 効果 |
|---|---|---|
| D1 | **原 GT 20 クラスは不変**。ループはこれを書き換えられない | 評価の錨が失われない |
| D2 | **毎ラウンド M₀ から再学習** | 表現ドリフトの複利化を断つ |
| D3 | **昇格ゲート（G1〜G7）** | 低品質クラスの流入を阻止 |
| D4 | **疑似ラベルの信頼度重み付け** | ノイズラベルの勾配寄与を抑制 |
| D5 | **語彙のバージョン管理**。各クラスに導入ラウンド・provenance・信頼度を記録 | ロールバック可能 |
| D6 | **再検証**: 既昇格クラスのインスタンスを毎ラウンド 10% 再キャプションし、重心が δ > 0.2 移動したら**降格** | 定義のなし崩し的変質を検出 |
| D7 | **tripwire**: 原 20 クラス mAP を毎ラウンド監視 | 崩壊の早期検出 |

**監視すべきドリフト指標**（毎ラウンド必ず記録する）

- **Taxonomy Stability**: 前ラウンドから、改名/マージ/降格されたクラスの割合
- **Vocabulary Growth**: 昇格クラス数の推移（急増は過分割の兆候、0 は飽和）
- **Centroid Drift**: 各クラスのキャプション重心の移動距離
- **Known-20 mAP**: tripwire
- **疑似ラベル数の推移**: 爆発的増加は偽陽性の連鎖を示唆

**Vocabulary Growth が単調増加し続けるのは良い兆候ではない。** 実在するクラスは有限なので、健全なループは飽和カーブを描くはずである。線形以上に増え続けていたら、それは概念の過分割か偽クラスの生成である。

## 8. 評価プロトコル

### 8.1 Part I（未知検出）の指標

| 指標 | 定義 | 役割 |
|---|---|---|
| **U-Recall** | 未知物体の再現率 | 主要指標 |
| **Known mAP** | 既知20クラスの mAP@0.5 | 制約条件（劣化の上限を管理） |
| **WI** (Wilderness Impact) | P_known / P_known∪unknown − 1 | 未知混入による既知精度の劣化 |
| **A-OSE** | 未知を既知クラスとして誤検出した絶対数 | 実運用での誤警報量 |
| **FPS** | T4 + TensorRT FP16, batch=1 | リアルタイム制約の検証 |
| **AURC** | 未知スコアの閾値を掃引した Recall 曲線下面積 | 閾値非依存の手法比較 |

**既知 mAP 単独で評価しないこと。** U-Recall を上げれば mAP は必ず下がるため、必ずペアで報告する。

### 8.2 Part II（語彙拡張）：発見クラスと GT クラスの対応付け

発見されたクラスは LLM が命名した自由文字列であり、COCO のクラス名とは一致しない。**評価設計そのものが本研究の方法論的な課題である。**

**インスタンスベースのマッチング**（命名の良し悪しを混入させないため、名前では対応付けない）。

```
1. 評価セットで、発見クラス c と GT クラス g の検出 box を IoU ≥ 0.5 で対応付け
2. 分割表 N[c][g] を構築
3. Hungarian 法で発見クラス → GT クラスの 1対1 対応を決定
4. 対応が付かなかった発見クラスは「偽クラス」として計上
```

### 8.3 Part II の指標

| 指標 | 定義 |
|---|---|
| **Vocabulary Recall** | 未知60クラスのうち、対応する発見クラスが存在する割合 |
| **Vocabulary Precision** | 発見クラスのうち、GT クラスに対応が付いた割合 |
| **Discovered-class mAP** | 対応付け後の、発見クラスに対する mAP@0.5 |
| **Naming Accuracy (strict)** | LLM 命名と対応 GT クラス名が意味的に一致する割合（text embedding cos ≥ 0.8） |
| **Naming Accuracy (hierarchy-aware)** | 上位語・下位語も正解とする（§8.4） |
| **Clustering NMI / Purity** | 発見クラスタと GT クラスの一致度 |
| **Known-20 mAP** | 原クラスの維持（tripwire） |
| **U-Recall (残存)** | まだ発見されていない物体の再現率 |

### 8.4 粒度不一致の扱い

ループが `golden retriever` と `poodle` を別クラスとして発見し、GT が `dog` 一つだった場合、strict 評価では**過分割として減点されるが、これは本当に誤りか。**

実用上はむしろ有益な粒度である可能性があるため、以下を併記する。

- **strict**: 1対1 対応のみ正解
- **hierarchy-aware**: 発見クラスが GT クラスの下位語（hyponym）であれば正解とする。判定は WordNet + LLM の併用
- **粒度比**: 発見クラス数 / 対応 GT クラス数（> 1 なら細分化傾向）

### 8.5 評価の循環を避ける

**命名に使った LLM を、命名の評価に使ってはいけない。** 同じモデルは同じ語彙バイアスを持つため、自己採点になる。

- 命名: Qwen2.5-7B（ローカル）
- 自動評価: 別系統のモデル + text embedding
- **人手検査: 発見クラス全件の名前と代表画像 5 枚を目視し、妥当性を3段階評価**（発見クラス数はせいぜい数十なので実行可能。これを最終根拠とする）

## 9. 成功基準と Go/No-Go 判断

### 9.1 成功基準

| レベル | 条件 | 判定 |
|---|---|---|
| **Gate（M₀ 確定）** | E4 が E0 比で U-Recall ≥ 10%、Known mAP 劣化 ≤ 3pt、FPS ≥ 100 | Week 3 末 |
| **Minimum** | E-main が 3R で 5 クラス以上を昇格させ、Known-20 mAP 劣化 ≤ 3pt | Week 6 末 |
| **Target** | Vocabulary Recall ≥ 25%（60クラス中15）、Naming Accuracy (hierarchy-aware) ≥ 60%、Known-20 劣化 ≤ 2pt。かつ **E-main > E-visual が Discovered-class mAP で 3pt 以上** | Week 7 末 |
| **Stretch** | Vocabulary Recall ≥ 40%、ラウンド3まで単調改善、E-main ≈ E-oracle（命名がほぼ上限に達している） | Week 8 |

**Target の最後の条件が本質である。** 言語経由が視覚クラスタリングに勝てないなら、DAM と LLM を使う理由がない。

### 9.2 Go/No-Go 判断点

- **Week 2 末**: E2 で objectness が飽和（全クエリで o(q) > 0.9）した場合、即座に λ_obj と Σ 正則化の調整に戻る。飽和したまま先へ進まない
- **Week 3 末**: E4 が Gate を満たさない場合、H2 が棄却された可能性がある。E3 / E4 のうち U-Recall が高い方を M₀ 候補とし、それでも 10% 未満なら **C5（SAM2 疑似ラベル）をフォールバックとして投入**して M₀ を作り直す（+1 週、Part II の E-oracle / E-nogate を削減して吸収）
- **Week 5 末**: E-visual の結果を見て、E-main が勝つ見込みを評価する。見込みが薄い場合は DAM プロンプトの改善を先に行う

## 10. リスクと緩和策

| リスク | 深刻度 | 兆候 | 緩和策 |
|---|:-:|---|---|
| **誤り増幅（自己確証バイアス）** | **最高** | ラウンドごとに疑似ラベル数が急増、Known-20 mAP が単調低下 | D1〜D7 の多層防御。tripwire で強制停止・ロールバック。E-nogate で壊れ方を事前に把握 |
| **objectness の飽和** | 高 | 全クエリで o(q) → 1、U-Recall は高いが A-OSE が爆発 | λ_obj を下げる、Σ の shrinkage λ を上げる、C3 の k_bg を絞る。Week 2 で必ず検出する |
| **頻出「モノ」クラスの支配** | 高 | 発見クラスが person, tree, building, sky で埋まる | G7（空間的多様性）と、stuff 語彙（LLM が「不可算・背景的」と判定した名前）の棄却リスト |
| **部分 / 全体の混同** | 高 | 「wheel」「handle」「window」が独立クラスとして昇格 | SAM2 整形時の面積縮小率を記録し、G5 の LLM 衝突判定に「これは既存クラスの部分か」を明示的に問う |
| **既知 mAP の大幅劣化（Part I）** | 中 | E3/E4 で 5pt 超の低下 | C3 の ignore 対象を objectness 上位 k から、より保守的な条件に限定する |
| **H2 の棄却** | 中 | E4 が E3 を上回らない | 想定内。「query selection は RT-DETR の未知検出のボトルネックではなかった」という知見自体が報告価値を持つ。M₀ は E3 で代替 |
| **粒度の不安定** | 中 | ラウンド間で同じ概念が分裂・統合を繰り返す | Taxonomy Stability を監視。閾値超過で HDBSCAN の min_cluster_size を上げる |
| **DAM の幻覚** | 中 | 小・ボケ box で無内容なキャプション | 面積下限 0.3%、生成長制限、G2 の凝集度で自然に除去される |
| **E-visual に勝てない** | 中 | Target の最終条件を満たさない | **想定内の結果として報告する**。「検出タスクの語彙獲得において言語モデルの寄与は限定的」という知見自体に価値がある。ただし DAM プロンプトの改善余地は先に潰しておく |
| **長尾クラスが永久に昇格しない** | 中 | Vocabulary Recall が 20% 前後で頭打ち | 未昇格プールのラウンド跨ぎ蓄積（§6.6）。G1 を後半ラウンドで緩和する案も検討 |
| **Σ の数値不安定** | 中 | Cholesky 分解が NaN | 対角近似 + 低ランク補正へフォールバック。実装時点で両方用意しておく |
| **評価コードの不整合** | 中 | 文献値と E0 の mAP が乖離 | Week 1 で PROB 公開実装を再現実行し、評価スクリプトの健全性を先に確認する |
| **単一GPUでの時間超過** | 中 | Week 3 時点で E4 未完 | E-nogate / E-oracle を削減。任意実験（§5.2）は放棄 |
| **DAM 推論コストの超過** | 低 | Stage B が 1 ラウンド 8 時間超 | 画像あたり box 数を 3→2 に削減。キャプションは必ず永続化し再生成しない |

## 12. 実装上の要点

### 12.1 語彙の状態管理

クラス定義は以下のスキーマで永続化し、ラウンドごとにスナップショットを取る。

```json
{
  "class_id": 21,
  "name": "traffic cone",
  "aliases": ["orange cone", "road cone"],
  "introduced_round": 1,
  "status": "active",            // active | demoted | merged
  "merged_into": null,
  "caption_centroid": [...],     // 1024-d (gte-large)
  "coherence": 0.81,
  "instance_count": 137,
  "image_count": 94,
  "mean_objectness": 0.72,
  "confidence_weight": 0.58,
  "provenance": ["img_00123#box2", ...]
}
```

provenance を持たせておくと、あるクラスが壊れたときにどの box が原因かを追跡でき、ロールバックが機能する。**これを省略すると、ドリフトが起きたときに何もわからなくなる。**

### 12.2 再現性の担保

- **乱数**: 全 run で 3 seed を回すのは資源上不可能なため、**最終手法 E-main のみ 3 seed**、他は seed=0 固定。分散を報告できるのは E-main のみである点を報告書で明記する
- **バージョン固定**: `requirements.txt` にハッシュ固定。PyTorch / CUDA / SAM2 / DAM / Qwen のバージョンを記録
- **ログ**: W&B に全 run を記録。config は Hydra で管理し、run ごとに完全な config を artifact として保存
- **チェックポイント**: E0、M₀（E4）、およびループの各ラウンドの学習チェックポイントは必ず保存。その他の中間実験は最終エポックのみ
- **コード**: 1 実験 = 1 コミット。experiment ID をコミットメッセージに含める
- **生成物の永続化**: DAM のキャプション（temperature 0）、Qwen の命名プロンプト・バージョン・命名結果、語彙スナップショットを全件保存。C5 使用時は疑似ラベル生成スクリプトと出力 JSON も固定保存
- **HDBSCAN** の乱数シード固定
